# ТЗ: каталог классов и блоки обучения

Статус: черновик на реализацию. Пилот v0.1 с четырьмя классами экскаватора остаётся готовым каталогом, не единственной задачей программы.

Спека пилота: `EXCAVATION_VIDEO_LAB_SPEC.md`. Сейчас классы зашиты в `configs/labels.yaml`, `DetectionClassName` и `LabelsConfig` (`src/excavation_lab/schemas.py`). Тексты интерфейса уже живут в двух каталогах, `ru` и `en` (`src/excavation_lab/ui/copy.py`, переключатель в `src/excavation_lab/ui/locale.py`).

## 1. Зачем

Оператор заводит новый рудник и другую технику, не начиная программу заново. Он берёт уже обученную модель или ещё не обученную, добавляет новые классы рамок и дообучает её новому оборудованию.

Каталог классов и веса не принадлежат одному проекту. Удаление проекта их не стирает.

Ролик режется сразу на блок обучения, блок проверки и блок итоговой оценки. Отдельного шага «эпизоды заездов, потом предложить разбиение» в этой доработке нет.

## 2. Каталог классов

Каталог лежит в workspace, не в каталоге проекта.

Один класс:

| Поле | Правило |
|---|---|
| `id` | Целое `>= 0`, уникальное внутри каталога. `0` не фон. Новый класс получает следующий свободный id. Старые id не перенумеровываются. |
| `name` | Английский токен, уникальный внутри каталога. Уходит в COCO. Это идентификатор данных, не строка интерфейса. |
| `title` | Подпись, как её ввёл оператор. Показывается как есть в обоих языках интерфейса. |
| `box` | Одна фраза оператора, что входит в рамку. Попадает в инструкцию пакета CVAT как есть. |

`title` и `box` не прогоняются через каталоги `ru`/`en`. Через них идут только надписи программы: кнопки, шаги, ошибки, пустые состояния.

Общие и ненастраиваемые поля кадра те же: `visibility` (`clear`, `partial`, `unlabelable`), `review_status` (`unreviewed`, `reviewed`, `excluded`), атрибуты `truncated`, `instance_local_id`, `annotator`, `reviewed_at`, `note`.

В каталоге от 1 до 16 классов. Повтор `id` или `name` не записывается.

Готовый каталог `excavation` — сегодняшние четыре класса из `configs/labels.yaml`. Новый каталог оператор собирает сам или копирует существующий и дополняет.

Проект хранит ссылку на каталог, не копию, которая умирает вместе с проектом. Второй проект может ссылаться на тот же каталог.

Удаление проекта удаляет его ролики, кадры, разбиение и снимки. Каталог и файлы весов остаются.

## 3. Добавление класса в любой момент

Класс можно добавить до разметки, во время разметки и после снимка.

Старые кадры при этом не переписываются:

- уже нарисованные рамки старых классов остаются;
- кадр, проверенный до появления нового класса, не считается примером «этого класса нет»;
- отрицательный пример нового класса появляется только на кадре, который оператор проверил уже после добавления класса и рамку этого класса не поставил;
- пока такой проверки нет, кадр учит старые классы и не учит отсутствию нового.

Удалить или переименовать `name` класса, по которому уже есть рамки или который есть в сохранённых весах, нельзя. Добавление и правка `title` / `box` можно.

Новый класс сразу виден в экспорте CVAT. Уже скачанный ZIP старого состава импортируется в старые классы и не затирает кадры, проверенные под новым классом.

## 4. Дообучение новой технике

Обучение читает выбранные веса и каталог.

- Старт с официальных весов RF-DETR, если своих ещё нет. Такой чекпоинт по-прежнему не называется своим детектором.
- Старт с уже обученных весов этой программы. Голова сохраняет старые классы и получает выходы новых. Старые логиты не обнуляются.
- Число выходов головы равно числу классов каталога на момент запуска.
- `run_test=False`. Итоговая оценка — отдельная команда по блоку итоговой оценки.
- Снимок записывает, с какого каталога и каких весов он собран. Импорт сверяет классы по `name`. Неизвестное имя не приклеивается к соседнему классу.

Правила ковша, кузова и active learning экскаватора выполняются только когда в каталоге есть соответствующие классы профиля `excavation`. Чужой каталог их не запускает. Пустые измерения показываются как «не рассчитано» / `not calculated` по текущему языку интерфейса.

## 5. Блоки вместо заездов

На шкале ролика оператор ставит блоки трёх ролей: обучение, проверка, итоговая оценка. Это и есть разбиение. Кнопки «эпизод заезда» и «предложить разбиение» в целевом экране нет.

Блок — полуоткрытый интервал `[start_s, end_s)`. Блоки одной роли могут быть несколькими кусками. Интервалы разных ролей не пересекаются. Секунды вне блоков никуда не входят.

Текст помощи берётся из текущего языка интерфейса.

Для рамок оборудования:

- ru: «В блоке обучения должны быть все единицы и части оборудования, которые модель должна узнавать.»
- en: «The training block must contain every equipment unit and every part the model should recognize.»

Для будущего обучения действиям, тем же экраном блоков:

- ru: «В блоке обучения должны быть все действия.»
- en: «The training block must contain every action.»

Экран действий в этой доработке не строится. Строка помощи и роль блока для него фиксируются сейчас, чтобы разбиение не переделывать второй раз.

Дальше из блоков отбираются редкие кадры, как сейчас, с интервалом около 2 секунд. Кадры блока обучения не попадают в проверку и итоговую оценку.

Фиксация разбиения по-прежнему один раз закрывает границы блоков этого ролика. До фиксации границы двигаются.

## 6. Интерфейс

Надписи программы добавляются в оба каталога, `ru` и `en`. Идентификаторы в коде английские.

Создание проекта:

- выбрать существующий каталог или создать новый;
- каталог `excavation` в списке есть сразу;
- свой каталог редактируется строками `name`, `title`, `box`;
- проект без выбранного каталога не подставляет четыре класса экскаватора молча.

Страница данных:

- один шаг разбиения: шкала и три роли блоков, плюс текст помощи из раздела 5;
- шаг разметки перечисляет классы выбранного каталога и поле `box`;
- кнопка «Добавить класс» доступна и после начала разметки;
- контактный лист без рамок;
- экспорт кладёт в ZIP классы каталога на момент экспорта.

## 7. Приёмка

1. Каталог `excavation` по-прежнему содержит четыре нынешних класса. Проект, который на него ссылается, экспортирует и учит их как до доработки.
2. Удаление проекта не удаляет каталог и не удаляет `weights.pth`, на которые ссылались другие проекты.
3. Новый проект на другом руднике подключает тот же каталог и те же веса. Добавление класса `shovel` после уже проверенных кадров разрешено.
4. Кадр, проверенный до добавления `shovel` и без рамки лопаты, не попадает в снимок как negative этого класса.
5. Кадр, проверенный после добавления `shovel` без рамки лопаты, попадает как negative.
6. Дообучение со старых весов сохраняет старые классы и добавляет выход нового. Официальный COCO-чекпоинт при этом не называется своим детектором.
7. Ролик режется блоками обучения, проверки и итоговой оценки. Отдельного назначения «заезд → train» на экране нет. Текст помощи есть в `ru` и в `en`.
8. Кадры из блока обучения не оказываются в проверке и итоговой оценке.
9. `uv run pytest tests -q` и `uv run ruff check src tests` проходят. Запуск обучения на пилоте не считается доказательством качества модели.

## 8. Вне этой доработки

- Экран разметки и обучения действий. Для него уже задано только правило блока: в обучении должны быть все действия.
- KPI заездов.
- Произвольные атрибуты CVAT сверх текущего списка.
- Удаление класса, по которому уже есть рамки или веса.
